# FE-CAL-01 — Calendar & Scheduling integration

`CalendarSchedulingPage` is exported from `CalendarSchedulingPage.tsx`. The existing `orderPlanningRoutes` array in `portfolioRoutes.tsx` now retains `/orders/portfolio` and adds `/orders/calendar`. Current main.tsx already supplies that array to `App.routeExtensions`; no shared change is necessary. Static Calendar and Portfolio registrations outrank `/orders/:id` in actual App tests. Queue, Portfolio and Calendar link to one another; existing Orders Sidebar active prefixes cover both static pages. No `/calendar` alias or second competing scheduler was added.

Production uses `unavailableScheduleSource`: no HTTP, fixture, job, delivery promise, reservation, conflict calculation or free capacity is invented. The Calendar remains navigable without data. All models in `calendarTypes.ts` are provisional feature-local presentation types, not canonical server DTOs. A future approved adapter must use the existing shared API/auth/signal utilities, map exact wire fields and call `validateSchedule`. There is no command method in `ScheduleSource`.

The read port takes a civil-date window `[from,toExclusive)` and explicit IANA time zone plus the existing auth context. Default business display is `Asia/Kuala_Lumpur`; another reviewed zone may be supplied through the page prop. Monday is the default week start, configurable to Sunday. Day moves by one civil date, week by seven, month by one calendar month clamping the chosen day to the destination month. Today uses the business zone. Month grids contain full weeks (28/35/42 dates); dates at the extreme ISO year boundaries are withheld where a complete view cannot be represented. No browser-local timezone is used for authoritative parsing.

`calendarDates.ts` strictly validates real civil dates and offset-aware ISO timestamps with seconds. Date-only delivery records remain civil dates, never midnight UTC. Instants retain original offset strings in detail display. Production intervals are `[start,end)` and must have positive millisecond duration. A midnight end does not occupy the next local date. Civil date arithmetic uses a UTC-noon carrier; actual event date placement uses Intl in the selected zone. DST tests cover spring 23-hour and fall 25-hour days and repeated offsets. No local-wall-time reschedule input or DST disambiguation command is offered. Leap seconds and sub-millisecond-only intervals are unsupported and fail closed.

Source identity requires exact tenant/actor, read authorization, known order IDs/request versions and resource IDs/versions, event/schedule/snapshot identities, current versions and unique IDs. Snapshot source evidence/currentness/expiry gate the entire loaded view. Refresh/failure/context changes hide old results and the inspector, and obsolete reads are aborted. Explicit retry only reloads reads; no automatic retry or optimistic mutation. Selection/filters are transient, reset with source/window/session revisions and never persisted. Redacted records have no exposed hidden title/order/status/resource/evidence values or filter options. The source contract must declare event existence/time/type safe to disclose and must redact private free text before supplying this port; this frontend cannot authenticate a server flag or sanitize arbitrary business prose.

Confirmed/tentative/simulation/history/unknown authority requires explicit source classification and evidence; missing authority evidence displays Unknown. Requested delivery is never confirmed authority. Delivery milestone labels distinguish REQUESTED, CUSTOMER_AGREED, DISPATCH_PLANNED, CONFIRMED_DELIVERY and ACTUAL_DELIVERY. They do not update agreement/fulfilment. Portfolio membership is never mapped to an event. Capacity gaps remain Unknown. FREE windows need explicit evidence and validated complete resource coverage; utilization is source-reported only with numerator/positive denominator/unit/basis/time-window/evidence and complete coverage. No inferred percentage or conflict severity is calculated. Missing conflict coverage stays unknown; only a complete source projection can report no matching source conflicts.

The event inspector is a nonmodal labeled region with close button focus, Escape close and focus return. P5 has no suitable generic read-only drawer; ConfirmationDialog is consequential-action confirmation and is deliberately not repurposed. No rescheduling preparation/submit/drag-and-drop exists; source-backed preview and execution remain unavailable until the full backend authority/version/idempotency/receipt/reconciliation contract is verified. All previous decision guards remain unchanged.

P5 components reused from actual `shared/ui.tsx`: EvidenceTierBadge, LastUpdated, ErrorState, EmptyState, UncertaintyNote, VersionConflictBanner and StatusBadge. Shared LastUpdated is used for Malaysia time only because its formatter suffix is MYT; other configured zones use the explicit zone/offset formatter. CSS is feature-scoped; desktop month uses seven columns, small screens have a horizontal month strip and stacked week/day views. No shared/global CSS, dependency or lockfile is changed.
