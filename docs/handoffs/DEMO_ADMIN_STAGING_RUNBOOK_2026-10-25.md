# Isolated Demo Admin HTTPS staging runbook

Status: prepared, **not deployed**. Use only for synthetic hackathon demonstration. One gateway replica is supported.

## Preferred $0 managed HTTPS path: Render Free

`render.yaml` provisions one Free web service and one Free PostgreSQL 16 database in Singapore. The one web container runs the public Demo Admin Gateway plus loopback-only FastAPI and an outbox worker; its supervisor restarts the container if a child exits. The database's `ipAllowList: []` disables external database connections. Render supplies the gateway's `onrender.com` HTTPS name and TLS; its load balancer forwards HTTP internally. The gateway derives the exact origin from Render's service identity and issues Secure cookies. Auto-deploy and preview environments are off. This is a temporary synthetic demo: Free web services sleep after 15 minutes idle and Free PostgreSQL expires after 30 days without backups.

1. Connect the Render app to Codex and authorize the GitHub repository in Render. Create a **new**, isolated Blueprint from this branch's `render.yaml`; do not attach existing services. Review the **Free** plan for both resources, Singapore region, loopback API process, and `ipAllowList: []` before creation. Stop if Render offers a paid plan.
2. In the Blueprint setup form, provide `MOUMANTAI_DEMO_ADMIN_USERNAME` and `MOUMANTAI_DEMO_ADMIN_PASSWORD_HASH` in Render's secret/environment inputs. Generate the verifier locally using `node frontend/scripts/hash-demo-password.mjs` with the password on stdin; never paste the plaintext password into Git, a CLI argument, or this chat. Render generates the separate private API key in the shared environment group. Use only synthetic demo data.
3. After deployment, confirm the `onrender.com` URL, FastAPI binds `127.0.0.1` inside the container, the worker has no listener, and PostgreSQL's external IP allowlist is empty. Run the public HTTPS login and negative tests, seed only synthetic fixtures through the approved private operational path, then run the Chrome Orders and C3 journeys against that URL. Do not register live provider webhooks or enable P4 sending.
4. Rotate the password verifier in Render encrypted environment settings and redeploy the gateway if access must be revoked. Gateway restarts revoke its in-memory sessions. Keep exactly one gateway instance.

## Alternative dedicated host path

1. Provision a dedicated host and DNS name. Permit inbound TCP 443 only to the gateway, limit SSH to the operator, and keep database and FastAPI ports closed. Put a valid certificate and private key in files outside Git (for example `/etc/moumantai/tls/demo.crt` and `/etc/moumantai/tls/demo.key`, root-owned with group read for container UID 1000, mode 640). The certificate must match the exact HTTPS origin.
2. On the host, check out this Draft PR's reviewed commit. Generate a unique 16+ character Demo Admin password without adding it to shell history. Pipe it to `node frontend/scripts/hash-demo-password.mjs` and store only the resulting `scrypt$16384$8$1$...` verifier. Generate a separate random 32+ character `DEMO_ISOLATED_API_KEY`. Never use a frontend `VITE_*` variable for either value.
3. Create a root-readable, untracked environment file outside the repository, for example `/etc/moumantai/demo-admin.env` (mode 600), with `STAGING_DB_USER`, `STAGING_DB_PASSWORD`, `STAGING_DATABASE_URL=postgresql+psycopg://<user>:<url-encoded-password>@db:5432/moumantai_staging`, `STAGING_ORIGIN=https://<fqdn>`, `DEMO_ADMIN_USERNAME`, `DEMO_ADMIN_PASSWORD_HASH`, `DEMO_ISOLATED_API_KEY`, `DEMO_TENANT_ID`, `DEMO_MANAGER_ID=user_manager_01` (or the single fixed server-approved manager), `DEMO_HTTPS_ORIGIN=https://<fqdn>`, `DEMO_HTTPS_PORT=443`, `DEMO_TLS_CERT_PATH` and `DEMO_TLS_KEY_PATH`. Use a dedicated synthetic tenant and a fresh staging database.
4. Validate the merged topology with `docker compose --env-file /etc/moumantai/demo-admin.env -f docker-compose.staging.yml -f docker-compose.demo-admin.yml config --quiet`. Inspect the resolved config: `api`, `worker` and `db` have no published ports; `gateway` alone publishes 443. Then run `docker compose --env-file /etc/moumantai/demo-admin.env -f docker-compose.staging.yml -f docker-compose.demo-admin.yml up -d --build`. The migration uses the existing staging preflight; API and worker use the stricter Demo Admin preflight. Do not expose the base Compose `frontend` loopback port through a public reverse proxy.
5. Check `https://<fqdn>/order-requests`: wrong password rejected; correct password creates a Secure/HttpOnly/SameSite cookie; refresh preserves the session; logout and expiry deny access. Check `/human-review` and `/` for C3 pending and decision history. Confirm forged identity headers, cross-origin mutations and missing CSRF return 403. Verify Orders review/accept and same-commitment Timeline with synthetic data, and verify all P4 provider outbound flags remain `false`. Do not register live provider webhooks or send messages for this gate.
6. Rotate the password verifier or private API key in the host environment file and restart gateway/API/worker. Gateway restart revokes all in-memory sessions. Keep the gateway at one replica; a shared revocable session store is required before horizontal scaling.
