## Approval boundary and narrow proposal

The `/v1/backend-v2/*` contract requires `X-Isolated-E2E-Key`, a configured manager and tenant. The new Vite serve-only `/demo-bff` middleware has an exact method/path allowlist, local same-origin operator bootstrap, opaque HttpOnly SameSite session, expiration/revocation, CSRF, header forgery denial, and server-injected identity/key. It delegates existing Orders/Core decisions. The Orders Owner approved this synthetic-only scope in PR #114 and waived additional P5 pre-implementation review for the isolated hackathon demo. No shared auth contract, backend DTO, business engine or migration changed. It is unavailable from production builds.

Local verification used migrated PostgreSQL 16, live API and worker. Genuine Chrome automation exercised persisted list, review, feasibility, acceptance, refresh, rejection, forged identity and missing CSRF. Orders' 17 HTTP tests passed on PostgreSQL, including authorization negatives, stale terms, duplicate acceptance and unresolved 202; the separate real HTTP/worker P3 test passed and verified same-Commitment `PENDING_P4_REVIEW` with `NOT_SENT`. The Chrome acceptance fixture had no recovery action, so no P4 intent existed in that browser run; its P3 link and same-Commitment timeline rendered. P1 inbound is not automatically converted to a Mock OrderRequest and no provider send was enabled. Final GO/NO-GO follows exact-head CI.
